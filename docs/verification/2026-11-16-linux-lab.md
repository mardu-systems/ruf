# Linux Asterisk runner and TLS observation verification

Observed on 16 November 2026 on Ubuntu 22.04.5 ARM64 in UTM, using the working
tree based on `e9660ce`. Toolchains were Bun 1.4.4, Rust/Cargo 1.98.1 and Docker
Engine/CLI 29.1.3 with Compose. The existing native Linux SDK was already built.

## Reproduced failures

The original `bun run test:asterisk` successfully measured returned echo audio
and passed all 17 Asterisk/interop cases, then failed two unrelated ignored Linux
notification tests. The blanket `--ignored` selection included tests requiring
the private session created by `bun run test:linux`; its session guards correctly
rejected execution in the SIP-only lab.

The original
`security_tests::trusted_tls_contact_ip_keeps_identity_and_other_hostname_cannot_borrow_connection`
also failed on the first isolated reproduction at the unchanged BYE assertion.
The engine had already reached local `Idle`, but the separate TLS peer process
had not yet logged the BYE. The expected rejection of the second hostname's
certificate remained intact.

## Minimal corrections

- Select both `asterisk_tests::` and `engine::interop_tests::` in the ignored-test
  invocation. Comparing the executable's discovered names before/after selection
  confirmed that all 17 lab cases remain selected. The two excluded OS-service
  cases still run through their dedicated Linux session runner.
- Reuse the TLS fixture's existing six-second condition wait until the call is
  locally idle **and** the peer has logged the BYE. Retain the DNS, ACK, BYE,
  certificate-rejection and SRTP assertions. No fixed sleep, whole-test retry or
  longer timeout was added.

No production SIP/audio, native ownership, thread, authorization or trust-store
code changed. No new dependency, command option or IPC/DTO contract was added.

## Complete Linux run without VM-specific test fixes

The previous VM-only runner and TLS backup were archived. All 109 relevant
tracked Rust, native, lab-script and fixture files were checked against the
repository by SHA-256; no extra Rust source remained in the guest crates. The
runner used real Cargo and `/usr/bin/docker`, not the Fedora prebuilt-test shim.

`bun run test:asterisk` completed with exit status 0:

| Stage                                          | Observed result                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| SIP registration, call and real echo recording | Passed; 4.04 s, RMS 5792, returned frequency 437.5 Hz, within the existing 420–460 Hz assertion. |
| Both Asterisk/interop test groups              | 17 passed, 0 failed; 62.82 s.                                                                    |
| Complete controlled TLS/SRTP security group    | 14 passed, 0 failed; 6.67 s.                                                                     |
| Previously flaky TLS case, separate repetition | 10 consecutive passes before the full run.                                                       |

The headless Linux runner retains its documented skip of the macOS/Windows-only
desktop saved-account startup case. None of the 17 Linux lab or 14 security cases
was skipped. Negative certificate/crypto scenarios intentionally emitted native
rejection diagnostics while their assertions passed.

The separate regular `bun run test:linux` passed all six OS-service/failure cases.
Host portable workspace tests passed 157 cases and UI tests passed 159 cases.
Host workspace Clippy and Linux adapter Clippy with `native-test-hooks`, all
targets and warnings denied, passed. Format, Svelte/TypeScript, frontend build,
version consistency and stable generated contracts were checked as well.

Only standard toolchain/environment setup was used; no VM-only runner,
uncommitted guest timing patch, disabled assertion, expanded TLS timeout or
certificate/trust bypass was required. The disposable Asterisk Compose service
was stopped after verification.

These are local ARM64 synthetic-media/controlled-peer observations. Hosted CI,
Linux x86_64, physical microphone/headset audio, real GNOME/KDE credential restore
and the remaining [desktop acceptance](2026-11-16-linux-desktop.md) are still
separate requirements.
